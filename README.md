# seunghoon — A 필터가 움직임을 플래시로 오인하는 문제

`Kim&Moon` 의 컷 불응기가 **"필터가 안 켜지는"** 문제를 고쳤다면, 이 브랜치는
그 반대편 **"필터가 잘못 켜지는"** 문제를 고친다. 경로가 달라 서로 간섭하지 않는다.

**순 방향성 관문 하나로 헤일로가 1/4 이 되고, 악화 4편이 전부 사라진다.**

측정 2026-08-16~17 / RTX 3050 Laptop 4GB / torch 2.5.1+cu121 / 심판 `pse_bt1702`

---

## 1. 무엇이 문제였나

`psecore`(필터가 쓰는 검출기)에는 **순 방향성이 없다.** `pse_bt1702`(심판)에는 있다.

화소 단위로 보면 팬과 플래시는 구분되지 않는다. 카메라가 움직이면 어두운 벽에
있던 화소 자리에 밝은 창문이 들어오고, 그 ΔY 는 플래시의 정의를 그대로 만족한다.

심판은 `net = 밝아진면적 - 어두워진면적` 으로 막는다. 팬은 양쪽이 맞먹어
상쇄된다(실측 0.239 / 0.237 → 0.089 vs 점멸 1.000). 필터는 대신 위상상관
움직임 보상으로 막는데, `psecore` 자신이 한계를 적어 두었다:

> "움직임 보상은 전역(팬) 한정이다. 국소 물체 움직임은 보상되지 않는다."

줌·회전·**피사체 움직임**에서는 뚫린다. 숏폼은 인물이 크게 움직이고 줌이 잦아
최악의 조합이다.

## 2. 고친 것 — `filters/`

`Kim&Moon` 최신본(`cut_min_gap_s` 불응기 포함) 위에 얹었다. **전부 기본 off.**

| 플래그 | 내용 | 판정 |
|---|---|---|
| `net_directional` | `up`/`dn` 면적 차가 `arm_area` 미만이면 개입하지 않는다 | **채택 권장** |
| `net_hyst` / `net_hold` | 관문 진동 억제 (임계 / 시간) | 기각 — 아래 4절 |
| `warp_alpha` | 알파맵을 `prevV`·검출기 링과 같은 이동량으로 워프 | 기각 (−1%) |

`PeakValley.step` 이 이미 `(up, delta, down|up)` 을 반환하는데 기존 코드는
첫 번째만 쓰고 하강분을 버리고 있었다. 재료가 이미 있었다.

## 3. 측정 — 불응기 위에서 재측정한 값 (`results_rebased.csv`)

앞선 70편·10편 측정은 **불응기 이전** 코드에서 나왔으므로, 대표 8편을
`Kim&Moon` 최신본 위에서 다시 쟀다.

| 조합 | 헤일로 평균 | 악화 |
|---|---|---|
| 기준 | 35.59 | **4/8** |
| **순방향** | **9.40** | **0/8** |

**악화 4편이 전부 사라진다.** 원본이 규격 적합인데 필터가 패턴 위반을 만들던
클립들이다 — 필터가 아예 개입하지 않는 것이 정답이었다.

| 클립 | 기준 | 순방향 |

| `DZ3fRSEvFoi` | 패턴 / 46.04 | **적합 / 0.00** |
| `DbvE_Zohmv6` | 패턴 / 41.83 | **적합 / 4.53** |
| `Dbs05gpxSuY` | 패턴 / 18.91 | **적합 / 3.65** |
| `Db2BKAWvAXs` | 적합 / 54.45 | 적합 / **2.27** |

### 미탐 검증 (`results_diag.txt`)

진짜 플래시를 놓치지 않는다.

| 클립 | 원본 | 순방향 |
|---|---|---|
| `cera_640` | 플래시 | **적합** (마스크 0.4002 → 0.3503, 314/507 차단) |
| `Db2D03pxZjy` | 플래시 | **적합** (헤일로 9.85 → 5.93) |

**관문이 무차별적이지 않다.** 속도 비용 14.0 → 22.7 ms/frame.

## 4. 기각한 것 — `net_hyst` / `net_hold` (`results_hyst.csv`)

`Db2LyhvyHI5` 은 순 방향성에서 헤일로가 **역행**하는 유일한 클립이다
(22.74 → 26.93). 원인은 규명됐다 — 관문이 임계 근처에서 진동해 마스크가
깜빡이고, **헤일로는 면적이 아니라 "새로 생긴 경계"를 재기 때문**이다.

`results_diag.txt` 의 토글 측정:

| 조합 | 토글 | 헤일로 |
|---|---|---|
| 순방향 | 13회 | 26.93 |
| 기준 | 5회 | 22.74 |
| 유지 | **1회** | **17.27** |

토글과 헤일로가 예외 없이 단조다. 그런데 `net_hold` 는 **1편을 고치고 2편에서
잃는다** — `Db155zGxJRf` 27.62 → 35.58, `Db2BKAWvAXs` 1.12 → 2.91. 관문을
붙잡으면 차단이 줄고(643 → 388), 불필요한 개입이 되살아난다.

임계 히스테리시스(0.7 / 0.5)는 세 클립에서 ±1% 라 무의미했다.

**→ `net_directional` 단독이 최선. `Db2LyhvyHI5` 역행은 알려진 한계로 남긴다.**

## 5. 배경 — 릴스 70편 3파전 (`results_reels_3way.csv`, `reels_3way_report.html`)

이 조사의 출발점. **주의: 불응기 이전 코드의 측정이다.**

Explore 무작위 100편 중 70편을 원본 해상도로 `A / D_ste / A→D_ste` 에 통과시켰다.

- 악화 A 4편 / D_ste 3편 / 체인 5편 — 전부 ③패턴 축
- 헤일로 A 중앙 18.67 vs D_ste 11.12. A 가 더 나은 클립은 20/70
- 체인은 61/70 에서 두 단독보다 나쁘다

원본 위반 10편이 **전부 패턴**이고 플래시가 0편이었다.

## 7. 실행

`harness/` 는 `psepipe_v3_seam/`(브랜치 `fix/ste-report-consistency`)의
`psecore` · `seam` · `tier` · `psepipe` 와 **같은 폴더**에 두고 실행한다.
`filters/` 의 두 파일로 덮어쓸 것.

```bash
export PYTHONIOENCODING=utf-8      # 없으면 출력 단계에서 cp949 로 죽는다
python run_rebased.py
```

주의: 입력 경로가 **제작자 로컬 절대경로로 하드코딩**되어 있다. 상단 상수를 고칠 것.

`results/logs/` 는 위 표들의 원본 출력이다.
