# seunghoon — A 필터가 움직임을 플래시로 오인하는 문제

실사 릴스에서 A 필터의 헤일로가 D_ste 의 2배로 나온 원인을 찾고 고쳤다.
**순 방향성 관문 하나로 헤일로가 절반이 된다 — 판정 손실 0.**

측정 기간 2026-08-16~17 / RTX 3050 Laptop 4GB / torch 2.5.1+cu121 / numpy 2.4.4

---

## 1. 무엇이 문제였나

`psecore`(필터가 쓰는 검출기)에는 **순 방향성이 없다.** `pse_bt1702`(심판)에는 있다.

화소 단위로 보면 팬과 플래시는 구분되지 않는다. 카메라가 움직이면 어두운 벽에
있던 화소 자리에 밝은 창문이 들어오고, 그 ΔY 는 플래시의 정의를 그대로 만족한다.

심판은 이걸 `net = 밝아진면적 - 어두워진면적` 으로 막는다. 팬은 양쪽이 맞먹어
상쇄된다(실측 0.239 / 0.237 → 0.089). 필터는 대신 **위상상관 움직임 보상**으로
막는데, `psecore` 자신이 한계를 적어 두었다:

> "움직임 보상은 전역(팬) 한정이다. 국소 물체 움직임은 보상되지 않는다."

즉 줌·회전·**피사체 움직임**에서는 마스크가 켜진다. 숏폼은 인물이 크게 움직이고
줌이 잦아서 최악의 조합이다.

이것이 세 증상을 한 번에 설명한다 — 잔상, A > D_ste 헤일로, 없던 패턴 위반 생성.

## 2. 고친 것 — `filters/`

두 수정 모두 **기본 off** 다. 켜지 않으면 기존과 완전히 동일하게 동작한다.
`pselive3.py`(CPU 기준판)와 `psegpu_full.py`(GPU) 양쪽에 들어 있다.

| 플래그 | 내용 | 결과 |
|---|---|---|
| `net_directional` | `up`/`dn` 면적 차가 `arm_area` 미만이면 개입하지 않는다 | **채택 권장** |
| `warp_alpha` | 알파맵을 `prevV`·검출기 링과 같은 이동량으로 워프 | **효과 없음 (−1%)** |

`PeakValley.step` 이 이미 `(up, delta, down|up)` 을 반환하고 있었다. 기존 코드는
첫 번째만 쓰고 하강분을 버렸다. 재료가 이미 있었던 셈이다.

## 3. 측정 — `results/`

### 실사 릴스 10편 × 4조합 (`results_fix_ab.csv`)

| 조합 | 헤일로 평균 | 마스크 평균 | 고침 | 악화 |
|---|---|---|---|---|
| 기준 | 24.95 | 0.5030 | 3/6 | 0 |
| 워프 | 24.64 (−1%) | 0.5030 | 3/6 | 0 |
| **순방향** | **12.48 (−50%)** | 0.2430 | **3/6** | 0 |
| 둘다 | 12.26 (−51%) | 0.2430 | 3/6 | 0 |

**고침·악화가 네 조합 모두 같고 헤일로만 절반이다.** 마스크 면적이 0.5030 →
0.2430 으로 줄었다 — 기존 필터는 개입할 필요 없는 곳에서 절반 가까이 개입하고 있었다.

개별 최대: `Db2BKAWvAXs` 52.44 → **1.12** (−98%), `Db19-xaNgBT` 6.38 → 1.31 (−80%).

**관문이 무차별적이지 않다.**

### 배경 — 릴스 70편 3파전 (`results_reels_3way.csv`, `reels_3way_report.html`)

이 조사의 출발점. Explore 무작위 수집 100편 중 70편을 원본 해상도로
`A / D_ste / A→D_ste` 에 통과시켰다. 08-15 실측(릴스 3편·360p)과 두 가지가 다르다.

- **악화 0 이 깨졌다** — A 4편, D_ste 3편, 체인 5편. 전부 ③패턴 축
- **헤일로가 뒤집혔다** — A 중앙 18.67 vs D_ste 11.12. A 가 더 나은 클립은 20/70 뿐
- 체인은 61/70 에서 두 단독보다 나쁘다 (08-15 의 A→D_full 결론과 같은 방향)

원본 위반 10편이 **전부 패턴**이고 플래시가 0편이었다. A 가 잘하는 축의 표본이 없다.

## 4. 아직 안 된 것

- **`Db2LyhvyHI5` 역행** — 10편 중 유일하게 헤일로가 늘었다(22.74 → 26.93).
  원인은 규명됐다: 관문이 임계 근처에서 진동해 마스크가 깜빡인다.
  토글 5회 → 13회, 차단 234프레임이 29개 구간으로 쪼개졌다 (`harness/diag_mask_toggle.py`).
  마스크 면적은 줄었는데 헤일로가 는 이유가 이것이다. **히스테리시스가 필요하다.**
- **합성 27클립 회귀 검증** — 기본값 승격 전에 08-15 의 지뢰를 다시 밟지 않는지 확인해야 한다
- **`warp_alpha` 는 채택하지 않는 쪽** — 1% 라 코드 복잡도를 감당할 근거가 없다

## 5. 실행

`harness/` 스크립트는 `psepipe_v3_seam/`(브랜치 `fix/ste-report-consistency`)의
`psecore` · `seam` · `tier` · `psepipe` 와 **같은 폴더**에 두고 실행한다.
`filters/` 의 두 파일이 그 브랜치 것보다 최신이므로 덮어쓸 것.

```bash
export PYTHONIOENCODING=utf-8      # 없으면 출력 단계에서 cp949 로 죽는다
python run_fix_ab.py
```

주의: `run3way_reels.py` · `run_fix_ab.py` · `motion_halo.py` 는 입력 경로가
**제작자 로컬 절대경로로 하드코딩**되어 있다. 옮겨 심을 때 상단 상수를 고칠 것.
