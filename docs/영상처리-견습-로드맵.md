# 영상처리 견습 로드맵 — 이 저장소를 교과서로 (2026-08-21)

영상처리·필터링·디스플레이를 완전 초보에서 숙련자까지 끌어올리는 훈련 과정.
일반 교재 순서를 따르지 않는다 — **이 저장소가 이미 각 주제의 실전 사례를
갖고 있으므로, 저장소의 부품을 백지에서 다시 유도하는 것**을 훈련의 축으로
삼는다. 각 단계는 목표 → 과제 → 잘 알려지지 않은 자료 → 지름길 → 졸업 기준
순서다.

---

## 0. 현재 과정 진단 — 무엇이 되어 있고 무엇이 비어 있나

산출물 기준으로 단계별 성취도를 매기면:

| 단계 | 주제 | 저장소의 증거 | 성취도 |
|---|---|---|---|
| 1 | 도구 (ffmpeg·OpenCV·NumPy) | 합성 클립 제작, 320px 분석 파이프라인 | 상 |
| 2 | 빛·색·감마 | sRGB EOTF 경계 보정 3층, 선형광 임계 | 상 |
| 3 | 공간 필터링 | **비어 있음** — 패턴 축 "항상 실패 (공간 연산이 없다)" | **하** |
| 4 | 시간축 필터링 | pselive3 슬루 제한 + 지뢰 6개 문서화 | **최상** |
| 5 | 색 과학·디스플레이 | 적색 규칙 구현. 단 `slew_chroma` 는 "경험값" | 중 |
| 6 | 코덱·전송·재생 | CRF16 인코딩 대조군, HLS 설계(미구현) | **중하** |
| 7 | 측정·실험 설계 | seam 발명, 2×3 요인설계, 회귀 관문, 지표혼동 경고 | **최상** |
| 8 | GPU·신경망 | psegpu_full 10.9배, BlazeBVD 재구현+학습 | 상 |

주목할 점: **비어 있는 단계(3·6)가 정확히 프로젝트의 남은 관문과 겹친다.**
패턴 축을 못 푸는 것은 공간 연산 지식의 공백이고(작업기록-0821 1절),
구간 저장이 설계에 머문 것은 HLS·코덱 실무의 공백이다(구간저장-토글-설계 6절).
못 배운 곳에서 못 만든 것이 나온다 — 그래서 이 로드맵의 과제는 전부
**남은 관문 목록에서 뽑았다.** 학습 진도가 곧 프로젝트 진척이 되도록.

또 하나. 4·7단계가 최상인 이유는 재능이 아니라 **관행**이다: 합성으로 먼저,
변수 하나씩, 대조군 통일, 실패를 코드 머리말에 지뢰로 박제, 매일 작업기록.
이 관행 자체가 이 저장소에서 배울 가장 값진 것이므로 모든 단계에서 유지한다.

## 1단계 — 도구: 영상을 배열로 다룬다 (1주)

**목표** 영상을 프레임 배열로 읽고 쓰고, 합성 테스트 클립을 스스로 만든다.

**과제**
1. `ffprobe -show_streams` 로 시연 영상 한 편의 코덱·해상도·fps 를 읽는다.
   `ffprobe -show_frames -show_entries frame=pict_type` 으로 I/P/B 나열까지.
2. ffmpeg lavfi 만으로 3Hz 흑백 스트로브 클립을 만든다. 그다음
   `legacy_detectors/make_testclips.py` 를 읽고 프로젝트가 왜 NumPy 로
   직접 만드는지 비교해 본다 (화소 값을 정확히 통제하기 위해서다).
3. OpenCV 로 프레임별 평균 휘도를 CSV 로 뽑아 그래프로 그린다.
   스트로브가 사각파로 보이면 통과.

**숨은 자료**
- trac.ffmpeg.org (공식 위키) — 구글 검색보다 여기 레시피가 정확하다
- `ffmpeg -f lavfi -i testsrc2` / `color` / `sine`: 다운로드 없는 테스트 소스
- OTTVerse 의 ffmpeg 레시피 모음

**지름길** 분석은 320px 로 줄여서 한다 — 판정이 CPU 실시간 수십 배속인
비결이 이것이다(아키텍처-개요 2절). 프레임 루프 안에서 파이썬 스칼라 연산을
하지 않는다. 전부 배열 연산으로.

**졸업 기준** 벡터화된 코드로 초당 수백 프레임을 처리한다.

## 2단계 — 빛·색·감마: 화소의 물리 (1~2주)

**목표** "8비트 20 스텝 차이"가 밝기에 따라 전혀 다른 물리량임을 계산으로
보인다.

**학습** sRGB EOTF ↔ 역함수, 선형광, BT.709 상대휘도 계수, Michelson 대비,
cd/m² 와 상대휘도의 관계.

**과제**
1. sRGB EOTF 를 직접 구현한다 (라이브러리 금지). 그다음 pselive3 지뢰 3번
   **"감마 공간에서 제한 금지"** 를 수치로 재현: 8비트 20 스텝이 어두운 영역과
   밝은 영역에서 각각 선형광으로 얼마인지 표를 만든다. 밝은 쪽 0.136 이
   임계 0.10 을 넘는 것을 자기 손으로 확인한다.
2. `pse_bt1702.py` 의 경계 보정 3층 중 "조각별 sRGB EOTF" 를 읽고,
   왜 조각별로 해야 했는지 한 단락으로 설명해 본다.

**숨은 자료**
- Poynton, *Gamma FAQ* / *Color FAQ* (poynton.ca) — 30년째 이 분야 정본.
  짧고, 흔한 오해를 조목조목 깬다
- Poynton, *Digital Video and HD: Algorithms and Interfaces* — 방송·디스플레이
  수치의 출처를 추적할 때 마지막에 도달하는 책
- `colour-science` 파이썬 패키지 — 변환 공식 검산용

**지름길** 감마가 헷갈릴 때마다 한 문장으로 정리된다: **물리는 선형광에서
재고, 감마는 저장 포맷이다.** 이 프로젝트의 임계는 전부 선형광 기준이다.

**졸업 기준** 지뢰 3번의 seg6 사례(S 를 올렸더니 위반이 0.12s → 1.04s 로
역행)를 남에게 설명할 수 있다.

## 3단계 — 공간 필터링: 프로젝트의 공백 (1~2주)

**목표** 컨볼루션·경계 검출·블러를 손으로 구현하고, 부작용을 수치로 잰다.
이 단계가 채워져야 패턴 축(③)에 도전할 수 있다.

**학습** 컨볼루션, 가우시안(분리 가능성), Sobel, bilateral, 언샤프 마스크,
주파수 영역 직관(공간 주파수 = 패턴 규칙의 "줄무늬"가 사는 곳).

**과제**
1. 가우시안 블러를 NumPy 로 직접 구현하고 cv2 와 결과·속도를 비교한다.
   2D 커널 한 번 vs 1D 커널 두 번(분리)의 속도 차이도 잰다.
2. `seam.py` 의 헤일로 H 가 왜 "Sobel + p99" 인지 확인한다 — 평균으로 재면
   경계 링(~1% 화소)이 희석돼 하드 마스크와 평활 마스크가 구분이 안 됐다는
   1차 보정 실측을 합성 클립으로 재현해 본다.
3. **실전**: `psepipe` 작동기 B(패턴 대비 감쇠)를 읽고, pselive3 가 패턴을
   항상 놓치는 클립 하나를 골라 공간 필터로 패턴 대비를 낮추는 실험을
   설계한다. 판정은 pse_bt1702, 부작용은 seam 으로 — 기존 관행 그대로.

**숨은 자료**
- Szeliski, *Computer Vision: Algorithms and Applications* — szeliski.org/Book
  에서 무료 PDF. 3장(필터링)만 읽어도 이 단계가 끝난다
- dspguide.com — 무료 DSP 교과서. 컨볼루션 직관은 6~7장이 최고
- setosa.io/ev/image-kernels — 커널을 마우스로 만져보는 인터랙티브 페이지

**지름길** 공간 필터의 부작용 어휘는 이미 저장소에 있다: 헤일로(없던 경계),
펌핑(정지 화소 흔들림). 새 필터를 만들면 반드시 이 축으로 먼저 잰다.

**졸업 기준** "블러가 원리적으로 불가능한 필터"(pselive3)와 블러 있는 필터의
이질감 차이를 seam 수치로 제시할 수 있다.

## 4단계 — 시간축 필터링: 심장 (2~3주)

**목표** pselive3 를 백지에서 다시 만들 수 있다. 이 프로젝트 기술의 핵심이자,
일반 교재에 거의 안 나오는 부분이다.

**학습** 화소를 시계열로 보기, IIR/EMA vs 슬루 제한, 인과성·지연·상태 O(1),
컷 검출(대비 정규화 NCC — 히스토그램이 안 되는 이유 포함), 움직임과 점멸의
구분, 3~30Hz 위험 대역.

**과제 — 지뢰 순례** `pselive3.py` 머리말의 지뢰 6개를 **각각 합성 클립에서
재현하고 해결한다.** 읽고 넘어가면 안 남는다. 겪어야 남는다.

| 지뢰 | 재현할 것 |
|---|---|
| 1 머리 프레임 누락 | 버퍼형 필터로 앞 1.4초 생스트로브 통과 |
| 2 섬광을 컷으로 오인 | 히스토그램 컷 검출 + 전면 스트로브 → 제한 무력화 |
| 3 감마 공간 제한 | 2단계에서 이미 재현 |
| 4 휘도만 보면 색 점멸 놓침 | 등휘도 적↔녹 합성(03)에서 마스크 불발 |
| 5 성분별 클리핑의 색상 회전 | 순수 적색 위반에 없던 BY 위반 생성 |
| 6 페더링이 보증을 깬다 | 페더 5px vs 0 으로 면적 규칙 재위반 |

이후: 미니 슬루 필터(~50줄)를 직접 짜서 합성 03/08/10/12 에 걸고
pse_bt1702 로 재판정, pse_spectrum 으로 3~30Hz 에너지 전후 비교까지.

**숨은 자료**
- dspguide 14~19장 — 디지털 필터. IIR 의 상태·안정성 개념이 여기 있다
- TestUFO / blurbusters.com — 시간축 아티팩트(모션 블러·잔상·PWM)를 눈으로
  보는 사이트. 디스플레이 쪽 5단계와도 이어진다
- `psepipe_v3_seam/validation/` 의 CSV 와 md — **이 자체가 교재다.**
  수치가 어떤 실험에서 나왔는지 커밋 메시지와 함께 역추적하는 훈련

**지름길** 실사 전에 합성. 합성에서 안 되는 것은 실사에서도 안 된다.
그리고 상태를 가진 필터를 디버깅할 때는 화소 하나를 골라 시계열을 그린다 —
프레임 이미지를 보는 것보다 10배 빠르다.

**졸업 기준** `S = safety × θ / n_look` 유도를 화이트보드로 설명하고,
"왜 성분별로 자르면 색상이 회전하는가"에 벡터 그림으로 답할 수 있다.

## 5단계 — 색 과학과 디스플레이 (2주)

**목표** `slew_chroma` 같은 "경험값"을 근거 있는 값으로 대체할 수 있다.
디스플레이가 화소를 어떻게 빛으로 바꾸는지 안다.

**학습** CIE XYZ → u′v′ 좌표, Δu′v′ 색차, BT.1702 적색 규칙(채도비 0.8 +
Δu′v′ 0.2)의 구조. 디스플레이 물리: LCD/OLED 응답 시간, PWM 디밍(그 자체가
점멸원이다), HDR(PQ/HLG, BT.2100), 톤 매핑이 임계에 미치는 영향.

**과제**
1. ★ 작업기록-0821 2절의 발견을 이어받는다: `slew_chroma` 가 선형광
   **절대량** 상한이라 밝은 화소만 회백화되는 문제 — 이것을 Δu′v′ 기반
   **상대** 상한으로 유도해 본다. 그다음 남은 검증 그대로: 합성 등휘도 클립
   06/07 에서 ②적색을 놓치지 않는지 확인한다. 통과하면 기본값 변경의
   근거가 완성된다.
2. 붉은 무대 조명 회백화 증상을 u′v′ 평면 궤적으로 시각화한다 — 원본과
   필터본의 색도 경로를 겹쳐 그리면 "직전 프레임에 갇힌다"가 그림이 된다.

**숨은 자료**
- **Fisher et al. 2005, Epilepsia** — "Photic- and pattern-induced seizures:
  a review for the Epilepsy Foundation of America Working Group".
  WCAG·방송 규격 임계값들의 원 출처 논문. 임계의 "왜"가 여기 있다
- ITU-R BT.1702-3 **원문** (ITU 사이트 무료 PDF) — 요약본 금지. ⑥ 프레임
  간격 사례처럼 허용 문언이 금지로 뒤집혀 전파된다. 원문 확인이 이 프로젝트
  에서 실제로 판정 오류 2건을 막았다
- W3C WCAG *Understanding SC 2.3.1* — 웹 쪽 임계의 유도 과정 설명
- **PEAT** (Trace Center, 메릴랜드대) — 무료 광과민성 분석 도구. Harding FPA
  의 무료 대안이고, `IRIS_교차검증` 같은 제3자 대조 상대로 쓸 수 있다
- NAB-J(일본민간방송연맹) 애니메이션 가이드라인 — 포켓몬 쇼크(1997)의 산물.
  방송 실무가 임계를 어떻게 운용하는지 보여준다

**지름길** 색차를 RGB 거리로 재지 않는다 — u′v′ 가 (근사) 균등 공간이라
임계 하나로 전 색역에 통한다. 적색 규칙이 Δu′v′ 로 쓰인 이유다.

**졸업 기준** `slew_chroma` 기본값 변경을 근거 표(억제 불변·채도 회복·등휘도
클립 통과)와 함께 제안할 수 있다.

## 6단계 — 코덱·전송·재생: 두 번째 공백 (2주)

**목표** 구간저장-토글-설계 6절(HLS)을 직접 구현할 수 있다. 필터가 아무리
좋아도 재생 화면까지 도달해야 서비스다.

**학습** I/P/B 프레임과 GOP, 키프레임 정렬(조각 이어붙임의 성패 —
`test_segments` 의 격자 정렬 테스트가 이미 다룬다), x264 CRF 와 화질,
HLS(m3u8, `EXT-X-BYTERANGE`, fMP4), Flutter `video_player` 가 ExoPlayer/
AVPlayer 래퍼라 URL 재생만 된다는 제약(설계 6절의 전제).

**과제**
1. `ffprobe -show_frames` 로 시연 영상의 GOP 구조를 그린다. 키프레임 간격이
   조각 경계와 어떻게 맞물리는지 확인.
2. 같은 영상을 CRF 16/23/30 으로 굽고 seam 으로 잰다 — "원본도 같은 CRF16
   으로 한 번 굽는" 인코딩 대조군이 왜 필요한지(작업기록-0821 1절) 몸으로
   확인하는 실험이다.
3. ★ 구간저장 구현 순서 1번: `GET /videos/{id}/playlist.m3u8` API 를 만든다.
   앱 전에 **hls.js 데모 페이지**로 검증한다. 그다음에야 앱 전환(2번),
   통짜 삭제(3번). 설계가 박아둔 순서를 지킨다.

**숨은 자료**
- howvideo.works — 코덱·컨테이너·스트리밍 전체를 훑는 인터랙티브 개론
- **RFC 8216** — HLS 규격 원문. 놀랄 만큼 짧고 읽힌다. m3u8 디버깅은
  블로그보다 이게 빠르다
- hls.js 데모 페이지 — URL 만 넣으면 세그먼트 로딩·에러를 즉석 확인
- Bento4 (`mp4dump`, `mp4info`) — mp4 상자 구조 해부 도구

**지름길** 세그먼트 이음매 문제의 대부분은 키프레임 비정렬이다. 조각 경계는
반드시 IDR 프레임에서 시작해야 한다 — 저장소의 "격자 정렬" 커밋(1c1923e)이
바로 이 문제를 다룬다.

**졸업 기준** `filter=on` 재생에서 원본↔조각 전환이 이음매 점프 없이 된다.

## 7단계 — 측정과 실험 설계: 모든 단계를 관통 (상시)

**목표** 숫자에 속지 않고, 남도 속이지 않는다. 이 프로젝트가 가장 잘하는
것이므로, 유지·전수가 목표다.

**이 저장소의 시범 사례** (각각 왜 그렇게 했는지 설명할 수 있으면 졸업)
- seam — PSNR/SSIM 이 "이질감"을 못 재서 지표를 발명했다
- 인코딩 대조군 — 비교 양쪽을 같은 CRF16 으로
- 2×3 요인설계(σ×net) — "헤일로를 낮추는 것은 σ 다"를 분리해 낸 도구
- regress_ab — 기본값 승격의 관문 (악화 0·퇴보 0)
- pse_spectrum — "판정만 통과" 지표 게이밍 방지
- 지표 혼동 경고(작업기록-0821 7절) — psecore 채널 초와 bt1702 6축은
  부분집합 관계도 아니다. **발표에서 가장 위험한 지점**

**과제**
1. `regress_ab.py testclips/*` 를 직접 돌려 관문의 실체를 본다.
2. 남은 측정 목록에서 하나를 골라(σ8 실사 확인이 적당하다 — seunghoon
   스윕은 360p·잔상 미측정이라 구멍이 명확하다) 스윕 → 작업기록 형식으로
   한 편 쓴다. 표·기전·한계·남은 검증까지 갖추면 통과.

**숨은 자료**
- Netflix 기술 블로그의 VMAF 시리즈 — 지각 품질 지표를 "설계"하는 과정의 정석
- MSU VQMT — 영상 품질 지표 비교 도구 모음
- Huff, *How to Lie with Statistics* — 얇지만 지표 혼동(7절 같은)의 예방주사

**지름길** 스윕에서 어떤 항을 3배로 바꿨는데 목적 수치가 소수점까지
동일하면, 그 항은 일을 안 하고 있는 것이다 — `slew_chroma` 발견의 패턴이고,
재사용 가능하다. 그리고 두 결과표를 비교하기 전에 반드시 묻는다:
**기준선(심판·인코딩·설정)이 같은가?**

**졸업 기준** 남의 결과표에서 기준선 불일치를 잡아낼 수 있다.

## 8단계 — GPU 가속과 신경망 트랙 (2~4주)

**목표** CPU 알고리즘을 GPU 로 옮기고, AI 필터를 공정하게 평가한다.

**학습** torch 를 학습이 아니라 **텐서 가속**으로 쓰기(psegpu_full 10.9배가
그 사례 — "딥러닝"으로 오해 금지, 아키텍처-개요 6절), CPU↔GPU 동치 검증,
옵티컬 플로우(RAFT), BlazeBVD 구조(STE / GFRM / LFRM / TCM,
`IMPLEMENTATION_NOTES.md` 가 논문 사실과 재구현 결정을 분리해 둔 모범).

**과제**
1. psegpu_full 가드 이식(남은 관문 2번) — `pselive3._guard` 를 텐서 연산으로.
   업로드형에서는 급하지 않지만 실시간 경로의 전제조건이다(작업기록 9절).
2. `verify_full.py` 악화 0 통과 — 승격 전제조건.
3. BlazeBVD 를 A 잔상 도메인으로 파인튜닝하고 `compare_ad` 로 D 슬롯
   재도전. 심판은 동일하게 — "공정 비교" 원칙 유지.

**숨은 자료**
- BlazeBVD 논문 + *Blind Video Deflickering by Neural Filtering with a
  Flawed Atlas* (CVPR 2023) — 이 분야 양대 축
- DAVIS 데이터셋 — 이미 학습에 쓴 그 코퍼스
- `validation/ad_ghost_synth.csv` — "왜 AI 가 기본 경로 밖인가"의 실측 근거.
  파인튜닝의 성패도 같은 표로 판정하면 된다

**지름길** GPU 이식 검증은 언제나 CPU 판과의 프레임 단위 일치부터
(`verify_full` 이 그 도구다). 성능 측정은 일치 확인 뒤에.

**졸업 기준** "AI 를 왜 기본 경로에 안 넣었는가"에 실측 표로 답할 수 있다 —
프로젝트가 이미 한 답변을 자기 손으로 재현하는 것.

## 나아갈 길 — 8주 예시

학습 과제를 프로젝트의 "남은 것" 목록과 겹치게 골랐다. 매주 재유도 과제
하나 + 작업기록 한 편이 기본 리듬이다.

| 주 | 내용 | 프로젝트 진척 |
|---|---|---|
| 1~2 | 1·2단계 압축 (지뢰 3번 재현 포함) | 발표 리스크 관리 — 지표 혼동(7절)·시연 라벨 정확성 점검 |
| 3~4 | 4단계 지뢰 순례 + 7단계 첫 작업기록 | `slew_chroma` 06/07 검증 또는 σ8 실사 확인 |
| 5~6 | 6단계 HLS | 구간저장 구현 순서 1→2→3 |
| 7~8 | 3단계 공간 필터링 **또는** 8단계 | 패턴 축 실험 설계 / psegpu_full 가드 이식 |

우선순위를 하나만 꼽으면 **6단계(HLS)** 다. 설계 문서가 "전제조건"이라고
못 박은 유일한 항목이고, 다른 학습은 미뤄도 프로젝트가 멈추지 않지만
이것은 저장 절감·토글 재생 전체가 걸려 있다.

마지막으로 — 이 저장소의 진짜 커리큘럼은 관행이다. 합성으로 먼저, 변수
하나씩, 대조군 통일, 실패는 지뢰로 박제, 원문으로 확인. 8단계를 다 돌고
나서도 이 다섯 가지가 남으면, 어떤 영상처리 문제 앞에서도 초보로 돌아가지
않는다.
