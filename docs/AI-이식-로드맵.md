# AI 모델 이식 로드맵 (2026-08-24)

전제 세 가지.

1. **통합 기점은 platform-mvp** — 워커 파이프라인(pse_bt1702 검출 →
   strong→base 2단 사다리 → 재판정)이 기준선이고, 이식 코드는
   `psepipe_v3_seam/` 에서 개발해 platform-mvp 로 병합한다 (psegpu_full
   백포트·REGRESS_0820 병합과 같은 경로).
2. **TOG24 사용 확정** — 학술 전용 라이선스 + 특허 출원 중이지만 본
   프로젝트는 사업화 단계가 아니므로 수용 (팀 결정 08-24). 단, 이 사실은
   발표·문서에 항상 병기한다. 상용 전환 시 이 슬롯은 재검토 대상 1호.
3. **승격 관문은 기존과 동일** — 어떤 이식도 `validation/regress_ab.py`
   회귀(합성 27 + 실사 209, GPU 노트북, `docs/GPU-노트북-실행-가이드.md`
   5절)에서 **악화 0·퇴보 0** 을 통과하기 전에는 기본 경로에 못 들어간다.
   REGRESS_0820 이 세운 기준 그대로다.

## 2. 권장 순서 1·2·3 — 실험 설계와 예상 결과

아래 "예상"은 전부 **[예측]** 이다 — 실측 전이며, 빗나가는 경우의 해석까지
미리 적는다 (REGRESS_0820 5절이 좋은 선례: 기각도 유효한 결과다).

### 1번 — 광원 인식 PoC (TOG24 + SAM2)

**설계.** 폴백 5클립(CIHun1gx7zU·PFSDW2g3D8o·UoHK74aS9sY·Y76O5wY7EcM·
xDdAHEUQ2zA) + strong 성공 대조 5클립 + cera. TOG24 를 키프레임(3fps)으로
돌려 R+ 마스크를 얻고, R+ 피크 좌표를 SAM2 프롬프트로 줘서 광원 영역을
전 프레임 추적한다. 클립당 영역 수·크기 분포·점유율을 CSV 로.

**[예측] 결과.**
- cera 천장 스트로브: 소형 광원 다수가 객체 단위로 추적됨 (기존 화소
  통계로는 "면적"만 보이던 것이 "몇 개, 얼마 크기"로 보이게 됨).
- 판별 신호가 갈릴 것으로 보는 근거: 누수 메커니즘이 "σ=32 질감 복원이
  32px 급 이하 구조를 복원"(REGRESS_0820 3절)이므로, 누수 5클립은
  **중앙값 영역 지름이 32px(분석폭 환산) 미만인 국소 광원 다수** 패턴,
  strong 성공군(전면 스트로브)은 대형 단일 영역 패턴으로 분리될 것.
- 성공 시: 5절에서 기각된 사전 분기(방식 2)가 부활 — 폴백 재실행(2.4%)을
  사전 회피하고, "영역 지름 < 문턱 → base 직행" 규칙을 회귀에 열로 추가.
- **실패 모드(정직).** 스트로브 소등 프레임에서 추적 단절(점등 프레임마다
  재프롬프트 필요), 블룸·헤일로 경계 흡수, 콘서트 특유의 과노출에서 R+
  가 음수 잔차(클리핑)와 혼입. 크기 분포가 또 겹치면 결론은 "사후 폴백
  유지 + 광원 마스크는 공간 가중 억제 연구로 전환" — 이것도 산출물이다.

**비용.** TOG24 ≈ 1초/장(논문 실측) → 3fps 키프레임 기준 60초 클립 ≈ 3분,
SAM2 는 실시간급. 11클립 PoC 로 4090 노트북 1시간 내. 산출물:
`validation/lightprobe_11clips.csv` + 판별 규칙 제안.

### 2번 — 화면전환 검출 업그레이드 (TransNetV2)

**설계.** 209편 + 합성 디졸브 클립에서 NCC 컷 vs TransNetV2 컷을 나란히
CSV 로. 이어 pse_chroma 의 스냅 시점을 TransNetV2 경계에 정렬한 변형을
경계성 클립(전면 색 교대 합성)에서 재판정.

**[예측] 결과.**
- 디졸브·점진 전환에서 NCC 미검출 다수, TransNetV2 가 프레임 정밀 경계 +
  신뢰도로 잡음. travis·pinkvenom 의 급전환 구간은 양쪽 일치 예상.
- 관문 부작용 화면전환 퇴보 3편(REGRESS_0820 3절, Db19aDiAxHJ 등)의 원인
  분리 가능: "관문이 만든 휘도 점프를 NCC 가 컷으로 오인"인지 "실제 컷
  증가"인지 — 전자라면 필터 쪽 컷 트리거 교체만으로 3편 회복 여지.
- pse_chroma 잔여 한계(경계성 원본에서 개입 시작 +2컷 초과) — 스냅을
  실제 컷 경계에 정렬하면 신규 화면전환 생성 감소 예상.
- 판정 축은 그대로: bt1702 화면전환 규칙은 불변, 교체는 **필터 내부
  트리거만**이다. 최종 재판정이 있으므로 오검출 리스크는 사다리가 흡수.

**비용.** 모델 초소형·CPU 가능, 209편 수 분. 산출물: 컷 비교 CSV +
pse_cut 백엔드 교체 여부 결론.

### 3번 — 회귀 화질 안전망 (VMAF)

**설계.** regress_ab 에 `--vmaf` 옵션: base/cand 출력 각각을 원본 참조로
ffmpeg libvmaf 채점, CSV 에 2열 추가. GPU 노트북 5절 명령에 그대로 편입
(Windows ffmpeg 7.1 gyan/BtbN 빌드는 libvmaf 포함 — 실행 전 확인 1줄).

**[예측] 결과.**
- 209편 대부분에서 **cand(σ32) VMAF ≥ base** — σ32 의 질감 보존 이득이
  지각 점수로 정량화됨 (발표 재료: "자연스러움을 수치로").
- 읽는 법 주의: 우리 필터는 원본을 **의도적으로** 바꾸므로 절대값이 아니라
  base 대비 Δ 로만 읽는다. 강억제 클립의 낮은 절대 점수는 정상.
- 누수 5클립은 VMAF 가 오히려 높게 나올 것 — "원본에 가깝다 = 억제가
  샜다"라서. VMAF 가 심판을 대체 못 하고 **보조축**인 이유가 데이터로
  증명되는 지점이다.
- 제안 규칙: `cand VMAF ≥ base − 3` 을 이질감 5축 옆의 보조 관문으로.

**비용.** 코드 소폭(옵션 1개 + 열 2개), 채점은 클립당 수 초. 산출물:
regress CSV 의 vmaf 열 + 보조 관문 문턱.

## 3. 통합 순서와 안전 원칙

1. 세 PoC 모두 **fix 브랜치에서 개발 → GPU 노트북 실측 → platform-mvp
   병합** (기존 백포트·병합 경로 재사용).
2. 파이프라인 변경은 사다리 구조를 건드리지 않는다: ①은 사다리 **앞**의
   사전 분기(실패해도 사후 폴백이 안전망), ②는 필터 **내부** 트리거,
   ③은 회귀 **계기판**. 판정 정본(pse_bt1702)은 셋 다 불변.
3. 기본값 승격은 항상 regress_ab 악화 0·퇴보 0 — 예외 없음.
