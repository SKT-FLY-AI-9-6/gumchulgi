# 아키텍처 개요 — 검출·보정 전체 구조와 각 부품의 역할 (2026-08-19)

새로 합류한 사람과 발표 준비가 읽는 문서다. 코드는 전부
`psepipe_v3_seam/`(브랜치 `fix/ste-report-consistency`), 실측 근거는
`psepipe_v3_seam/validation/`의 CSV와 커밋 메시지에 있다.

## 1. 서비스 형태와 전체 흐름

**업로드형 배치다.** 영상을 업로드하면 위험 구간·공간만 판단해 필터링된
결과를 저장한다. 실시간 스트림 서비스가 아니다 (아래 5절 참조).

```
영상 업로드
   │
   ▼
[1] 검출 — pse_bt1702 (심판, CPU, 룰 기반)
   │    6축 판정 + 위반 구간·공간(bbox) 확정
   ├── 적합 → 원본 그대로 저장 (무개입)
   ▼ 위반
[2] 1패스 필터 — pselive3 STRONG (빠름, 대부분 여기서 끝)
   │    플래시·적색 축을 위반 화소만 위험 임계 아래로 클램프
   ▼
[3] 재판정 — 같은 심판으로 출력 재검사
   ├── 적합 → 저장
   ▼ 불합격인 소수만
[4] psepipe 사다리 (느리지만 집요함)
   │    최소 강도부터 올려가며 보정→재판정 반복,
   │    화면전환 축은 디졸브, 새 위반 생기면 원본 유지(무해보장)
   ▼
저장 + 편집자 CSV (이벤트별 시각·bbox·규칙·권장조치)
```

역할 분담의 실증 (실사 3편, `validation/strong_real3.csv`):
pinkvenom·travis 는 [2]에서 완전 적합 (travis 는 디졸브 없이 화면전환
축까지), cera 는 가드 수리 전 [2]가 실패했고 [4]가 잡았다 — 폴백 사다리는
그 경우를 위해 존재한다.

## 2. 검출기 (판정 — 전부 룰 기반, CPU, AI 없음)

| 모듈 | 역할 |
|---|---|
| **pse_bt1702** | **정본 심판.** ITU-R BT.1702 — ①플래시(20cd/m²·Michelson 1/17·면적 1/4·3회/s) ②적색(채도비 0.8+Δu'v' 0.2) ③패턴 ⑤화면전환(3컷/s, pse_cut 내장) ④5초지속 ⑥시퀀스 간격. 경계 보정 3층(조각별 sRGB EOTF·병렬 묶음 계수·일관성 동의) 적용본. trace 138편 제3자 정답 대조 검증 |
| pse_comfort / pse_migraine | 편두통·불쾌감 축. **WARN 전용** — 규격 판정 미반영, 설문 검증 후 승격 |
| psecore | 정본 아님. 두 역할: (a) **필터의 검출 엔진** — PeakValley·FlashCounter·area_wcag·선형광 LUT 를 pselive3 가 import (지우면 필터가 깨진다), (b) 규격 밖 임상 채널(채널별 RGB) 단독 분석 도구 |
| legacy_detectors/ | 구세대 보관. 수정 금지 |

판정에 GPU 는 안 쓴다 — 320px 분석이라 CPU 로 실시간 수십 배속이고
GPU 심판은 존재하지 않는다. 대량 배치는 클립 단위 CPU 멀티프로세스.

## 3. 보정 필터 (전부 결정론적, AI 없음)

| 모듈 | 역할 |
|---|---|
| **pselive3** | **1패스 필터** (CPU). 화소별 변화율 제한(슬루) — 점멸을 없애는 게 아니라 위험 임계 바로 아래로 누른다. 내부: psecore 수학 기반 자체 검출 + 순방향 관문(채널별, 움직임 오개입 차단) + 자기감시 가드(조건부) + 컷 불응기 + 질감 복원(detail_sigma) |
| **psegpu_full** | 같은 알고리즘의 전 GPU 이식판, 10.9배 (720p 8.7ms/frame). torch 는 텐서 가속용 — **학습 가중치 없음, AI 아님.** 가드는 미이식 (OptF 주석 참조) |
| **psepipe** | 배치 사다리. 심판 폐루프(보정→재판정 반복), 작동기 B(패턴 대비 감쇠), 디졸브(화면전환), 무해보장, 편집자 CSV. `--actuator-d` 로 외부 보정기 슬롯 |
| BlazeBVD (blazebvd 브랜치) | **연구 트랙, 서비스 경로 밖.** 유일한 진짜 AI — GFRM/LFRM/TCM 신경망 재구현 + DAVIS 학습 체크포인트. 같은 심판으로 공정 비교한 실측(잔상 A의 2~3배 + 새 위반 생성, `validation/ad_ghost_synth.csv`)이 기본 경로 제외의 근거. 파인튜닝(A 잔상 도메인) 후 D 슬롯 재도전 |

### 모드 2개

- **기본 (Cfg())**: 자연스러움 우선 — 판정이 뒤집히는 최소한만.
- **STRONG (Cfg.strong() / --strong)**: "점멸이 강하게 나오는 영상을
  보이게 누른다" (팀 결정). net_directional + detail_sigma 32 +
  slew 0.65 + **arm_count 1.0(첫 플래시 무장)** + hold 0.5.
  강도의 실체는 slew 가 아니라 첫 플래시 무장이다 — slew 단독 하향은
  실사 3편 모두 효과 0 이었다 (`validation/strength_sweep_real3.csv`).

## 5. "실시간"이라는 말에 대해

pselive3 의 "실시간"은 서비스 형태가 아니라 **설계 혈통**이다 — 지연 0,
인과적(미래 프레임 안 봄), 메모리 O(1). 업로드형에서는 이 성질이 필수가
아니고, 우리는 이 필터를 **빠른 1패스 배치 보정기**로 쓴다. 그런데도 이
설계를 유지하는 이유:

1. **속도** — 사다리는 판정 폐루프라 라운드가 여럿 (cera 17초 클립 CPU
   5분+). 1패스는 한 번에 끝나고 GPU 면 초 단위다. 서버 처리량의 문제.
2. **STRONG 스타일이 1패스 필터의 동작이다** — 무장 구간 연속 억제
   (천장 스트로브가 눈에 보이게 잡히는 그 모습). psepipe 조명장은 반대로
   최소 개입이라 원본과 구분이 안 간다.
3. **확장 옵션** — 라이브 스트림·온디바이스·미리보기가 필요해지는 순간
   지연 0 설계가 그대로 자산이 된다.

발표에서는 "실시간 필터"보다 **"1패스 필터 (실시간 가능 설계)"**로
소개할 것.

## 6. AI 사용 현황 (요약)

- **서비스 경로: 학습된 모델 0.** 전부 검증 가능한 결정론적 신호처리 —
  의료 안전 영역이라 판정·보정의 본체는 무해보장이 되는 경로여야 한다.
- **연구 트랙: BlazeBVD 신경망 3단 재구현 + 자체 학습 완료.** 같은 심판
  체계로 공정 비교했고, 그 실측이 "왜 AI 를 기본 경로에 안 넣었는가"의
  근거 데이터다. AI 를 안 쓴 게 아니라, 만들어 재봤더니 아직 자체 필터를
  못 이겨서 파인튜닝 트랙으로 보낸 것.
- 주의: psegpu_full 의 torch 사용을 "딥러닝"으로 오해하지 말 것 (가속만).
