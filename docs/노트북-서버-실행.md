# GPU 노트북에서 서버 돌리기 (시연 구성)

스펙 2026-08-20 개정 4항 — 이 노트북이 서버, 폰의 Flutter 앱이 클라이언트.
Docker 는 GPU 접근이 번거로우므로 네이티브로 실행한다 (Docker/EC2 구성은
CPU 경로용으로 그대로 유지).

## 준비 (1회)

```powershell
pip install -r server\requirements.txt
python -c "import torch; print(torch.cuda.is_available())"   # True 확인
ffmpeg -version                                              # PATH 확인
```

폰이 접속하려면 Windows 방화벽에 8000 포트를 열어야 한다 (관리자
PowerShell — 직접 실행할 것):

```powershell
netsh advfirewall firewall add rule name="gumchulgi-api" dir=in action=allow protocol=TCP localport=8000
```

## 실행 (터미널 2개)

```powershell
powershell -ExecutionPolicy Bypass -File scripts\run_api.ps1
```

```powershell
powershell -ExecutionPolicy Bypass -File scripts\run_worker.ps1
```

워커 시작 로그에 `워커 시작 — 큐 폴링 중` 이 뜨면 준비 완료.
데이터는 `server\data\` (DB + media) 에 쌓인다.

## 폰 연결

1. 노트북과 폰을 **같은 와이파이**에 연결.
2. 노트북 IP 확인: `ipconfig` → 무선 LAN adapter 의 IPv4 (예: 192.168.0.7).
3. 앱 빌드/실행 시 주소 주입:

```powershell
cd app; flutter run --dart-define=API_BASE=http://192.168.0.7:8000
```

에뮬레이터는 주소 없이 그대로 (기본 `http://10.0.2.2:8000` = 호스트).

## 워커가 GPU 를 쓰는지 확인

업로드 1건 처리 중 `nvidia-smi` 에 python 프로세스가 잡히면 psegpu_full
경로다. CUDA 가 없으면 자동으로 pselive3(CPU) 로 떨어진다 — 동작은 같고
느릴 뿐이다. 사다리 채택 강도는 DB `videos.filter_level` 에 남는다.
