# psepipe_v3_seam 검증 결과 (2026-08-12)

`psepipe_v3_seam.zip` 을 풀어 검출 정확도·속도·구조를 검증했다.
이 폴더는 zip 내용에 **아래 수정 1건만 적용**한 실행 가능 사본이다.

## 적용한 수정

- `psefield.py`: zip·저장소 어디에도 없는 `pselive3` import 를 제거하고,
  유일하게 쓰이던 `_build_oetf()`(sRGB 역변환 4096-LUT)를 인라인했다.
  이 수정 전에는 `psefield → psepipe → tier` 임포트 체인이 전부
  `ModuleNotFoundError` 로 죽어 사용법.txt 의 1번 명령부터 실행 불가였다.

플래시 4회/s 위반으로 바뀐다. 문서의 설계 의도와 일치.

## 실행 검증 (수정 적용 후)

- `tier.py`: 정상 동작. 위반/안전 판정과 축별 여백 표 출력 확인.
- `psepipe.py v_flash5hz → out.mp4`: 사다리 9단째(chan a0.05 dn3.0)에서 적합
  전환, 출력 파일 독립 재판정도 적합. 6초 클립에 21초(0.28배속).
- `psepipe.py v_stripes → out.mp4`: **아래 버그 2 재현.** 0단이 "적합"으로
  오판 → 파일 재판정에서 `스트림 [] vs 파일 ['패턴']` 불일치 → 최종 출력 여전히
  패턴 위반.

## 남은 버그 (수정 안 함 — 원저자 확인 필요)

1. **폐루프 패턴 재판정 무력화** (`pse_bt1702.py` analyze → pse_pattern 호출):
   (a) 프레임 이터러블 경로에서 `fps` 를 pse_pattern.analyze 에 전달하지 않아
   ValueError → `pass: None` 으로 삼켜진다. (b) fps 를 넘겨도 메인 루프가
   제너레이터를 이미 소진해 패턴 분석기는 0프레임을 본다. 결과: need_B 사다리가
   0단에서 항상 "적합"으로 착각, 작동기 B 를 검증·최적화하지 못한다.
   수정 방향: 스트림 tee 또는 패턴 판정을 메인 프레임 루프에 통합.
2. `PatternFix.min_k=0.25` 하한 때문에 p2t 200cd 줄무늬는 최선이 50cd — 임계
   20cd 를 구조적으로 못 넘는다. 폐루프가 살아나도 극단 패턴은 B 로 못 고친다.
3. `pse_cut.analyze` 는 이터러블 미지원(cut_result 캐시로만 우회 중).
4. 판정기 이원화: psecore(sRGB, psefield.run 사용) vs pse_bt1702(BT.1886,
   psepipe 사용). apply_stream·uv_prime·적색 로직 중복 두 벌 — 드리프트 위험.
5. 성능: 판정 3채널이 같은 영상을 각자 디코드(3회). 1080p 5초에 플래시/적색
   1.9s + 패턴 2.4s + 컷 1.2s. 디코드 공유 시 약 2배 단축 여지.
