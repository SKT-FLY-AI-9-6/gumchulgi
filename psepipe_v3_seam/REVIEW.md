# psepipe_v3_seam 검증 결과 (2026-08-12)

`psepipe_v3_seam.zip` 을 풀어 검출 정확도·속도·구조를 검증했다.
이 폴더는 zip 내용에 **아래 수정 1건만 적용**한 실행 가능 사본이다.

## 적용한 수정

- `psefield.py`: zip·저장소 어디에도 없는 `pselive3` import 를 제거하고,
  유일하게 쓰이던 `_build_oetf()`(sRGB 역변환 4096-LUT)를 인라인했다.
  이 수정 전에는 `psefield → psepipe → tier` 임포트 체인이 전부
  `ModuleNotFoundError` 로 죽어 사용법.txt 의 1번 명령부터 실행 불가였다.

## 검출 정확도 — 정답 합성 클립 13편에서 13/13

플래시 4회/s 위반으로 바뀐다. 문서의 설계 의도와 일치.

## 실행 검증 (수정 적용 후)

- `tier.py`: 정상 동작. 위반/안전 판정과 축별 여백 표 출력 확인.
- `psepipe.py v_flash5hz → out.mp4`: 사다리 9단째(chan a0.05 dn3.0)에서 적합
  전환, 출력 파일 독립 재판정도 적합. 6초 클립에 21초(0.28배속).
- `psepipe.py v_stripes → out.mp4`: **아래 버그 2 재현.** 0단이 "적합"으로
  오판 → 파일 재판정에서 `스트림 [] vs 파일 ['패턴']` 불일치 → 최종 출력 여전히
  패턴 위반.

## 수정 2 — 폐루프 패턴 재판정 무력화 (2026-08-12 수정 완료)

증상: `pse_bt1702.analyze` 가 프레임 이터러블을 받으면 메인 루프가 제너레이터를
소진한 **뒤에** `pse_pattern.analyze(path)` 를 불렀다. (a) fps 미전달로
ValueError → `pass: None` 으로 삼켜지거나, (b) fps 를 넘겨도 0프레임을 보고
조용히 통과. 어느 쪽이든 need_B 사다리가 0단에서 "패턴이 고쳐졌다"고 착각해
작동기 B 를 검증·최적화하지 못했다.

수정: `pse_pattern.Stream` (프레임 단위 누적 API) 을 만들고 pse_bt1702 의
메인 루프에서 자기 디코드·축소 프레임(`small`)을 직접 먹인다. 기존
`pse_pattern.analyze(path)` 는 같은 Stream 을 쓰는 래퍼로 유지 — 결과 동일.

검증 (수정 후):
  · 정답 클립 13편 회귀 — 여전히 13/13.
  · v_stripes 를 제너레이터로 재판정 — 수정 전 `[]`(오판) → 수정 후 `['패턴']`.
  · psepipe v_stripes 엔드투엔드 — 사다리 각 단이 정직하게 "위반 패턴" 보고,
    `스트림 vs 파일` 불일치 경고 소멸.
  · 부수 효과: 패턴용 별도 디코드가 없어져 1080p 5초 전체 판정
    5.8s → 4.7s (0.87x → 1.07x 실시간).

## 수정 3 — 컷 채널 루프 통합 (2026-08-12 수정 완료)

`pse_cut` 에도 `Stream`(프레임 단위 누적 API)을 만들고 pse_bt1702 메인 루프에
통합했다. 효과 둘: (a) 프레임 이터러블 입력에서도 컷 판정이 가능해졌다
(이전에는 VideoCapture(path) 만 받아 예외가 pass=None 으로 삼켜졌다),
(b) 컷용 별도 디코드가 사라져 1080p 5초 전체 판정 4.7s → 3.7s (1.34x 실시간).
검증: 같은 클립을 경로/제너레이터로 재면 총 29컷·최대 6컷/s 로 완전 일치.

## 수정 4 — 작동기 B 가 고대비 패턴을 원리적으로 못 고치던 문제 (수정 완료)

두 겹이었다:

1. **곱셈 게인은 0 을 못 들어올린다** — 작동기 A 가 가산항(a_max)을 도입했던
   것과 같은 물리. 검정 바(Y=0)는 g 를 아무리 키워도 0 이라 밝은 바만
   내려가고, 명암차가 임계(20cd) 아래로 못 갔다 (실측 v_stripes 200cd:
   min_k 0.03 에서도 잔존 p2t 109cd). 목표 휘도 Yn 에 못 미친 만큼을
   **무채색 등량 RGB 로 가산**해 해결했다 — 휘도 가중치 합이 1 이라 Y 가
   정확히 그만큼 오르고, kap=1 인 곳(p2t<target)은 가산도 0 이라
   자기제한성은 그대로다.
2. `min_k=0.25` 하한이 kappa 를 target/p2t 까지 못 내리게 막았다.
   **B 세기 사다리**를 사다리 축(b_min_k: 0.25 → 0.10 → 0.03)으로 추가 —
   최소 개입 원칙대로 약하게 시작해 패턴이 안 잡힐 때만 세게 간다.

검증: v_stripes(200cd, 16쌍) — 수정 전 "전/후 모두 패턴 위반" →
수정 후 b0.10 단에서 **적합**, 출력 파일 독립 재판정도 적합.

## 수정 5 — psefield ↔ psecore 결합 완화 (수정 완료)

psecore(구판 판정기)는 psefield 의 레거시 단독 실행 경로(run/CLI)에서만
쓰이므로 모듈 수준 import 를 run() 안 지연 import 로 옮기고, set_eotf 의
sRGB LUT 를 인라인했다. psepipe 경로는 이제 psecore 를 전혀 로드하지 않는다.

## 머지 기록 — eb23c86 (프레임간격/시퀀스차이, ParkJin-Suk) 위로 리베이스

eb23c86 은 세 가지를 바꿨다:

1. **(보존)** 50Hz/60Hz 계열별 시퀀스 갭 — `seq_gap_s(fps)` (25/50fps 는
   0.360s = 9프레임, 그 외 0.334s). 좋은 개선. 참고: 24fps(영화)도 50Hz
   계열로 분류되는데 의도인지 확인 필요.
2. **(보존, 주의)** ⑥ 프레임간격을 `failed_rules` 에서 제외 — 판정 의미가
   바뀐다. 보고(`frame_separation`, `_sep` 구간)는 그대로지만 compliant 에
   반영되지 않는다. **결과: 334ms 안에 몰린 타이트 버스트(예: 2프레임 간격
   = 15Hz, 임상 최고 위험대역)가 ①의 시퀀스 규칙과 ⑥ 제외가 겹치며 '적합'이
   된다** (실측 v_burst334: 위반 → 적합 전환). 원저자 주석(2026-08-10 정정,
   "⑥은 별도 조항이 맞다")과 상충하므로 팀 확인 필요. 되돌리려면
   `failed.append("프레임간격")` 한 줄이다. psepipe 의 ⑥ 라우팅(컷유발 분류
   등)도 이 변경으로 실행되지 않는 코드가 됐다.
3. **(복원)** 구버전 파일 기준 편집으로 02afd12 의 패턴 Stream 통합이
   실수로 되돌아가 있었다 — 리베이스에서 복원했다 (1·2 는 유지).

## 수정 6 — jinsuk 브랜치 검출 개선 이식 (2026-08-12)

⑥ 제외는 의도로 확인됨(팀). origin/jinsuk 의 pse_bt1702 에서 세 가지를 이식:

1. **시퀀스 화소 동일성에 ±5% 팽창 허용오차** — 화소 정밀 일치는 규칙 취지보다
   엄격해 화면을 돌아다니는 스트로브의 시퀀스를 고아로 쪼갰다 (jinsuk 실측
   Test.mp4: 순수 계수 9회/s 인데 초반 30초 적합 → 팽창 후 위반 1.71s→3.21s).
2. **순수빈도 보조 채널** (`flash_raw`/`red_raw`) — 시퀀스 규칙 미적용 1초 창
   계수 = WCAG/ISO/NAB-J 식. 규격 판정에는 안 넣고 supplementary 로만 보고.
3. **저면적(10%) 보조 채널** (`flash_lo`) — 접근성 고시 문언에는 면적 조건이
   없어, 25% 미달 국소 점멸을 보조로 잡는다 (오탐 하한 실측 10%).

이식 검증: 회귀 12/12 유지. 이동 스트로브 합성 클립 — 규격 판정은 적합
(ITU 해석대로)이지만 순수빈도 5회/s 초과가 보조로 보고됨. 15% 국소 점멸 —
규격 적합 + 저면적 채널 5회/s 검출. psepipe 폐루프 정상.
