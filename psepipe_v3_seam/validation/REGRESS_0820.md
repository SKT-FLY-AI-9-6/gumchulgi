## 4. strong 프리셋도 6편에서 base 이하 (`strong_6clips_log.txt`)

`Cfg.strong()` = cand 두 손잡이 + slew_safety 0.65 + arm_count 1 + hold 0.5.
플래시 미탐 3편(CIHun·PFSDW·Y76O)이 cand 와 동일 — 3절 메커니즘의 예측대로
억제 강화로는 질감 복원 누수가 안 막힌다. strong 의 3편 근거(cera·
pinkvenom·travis)는 전면 스트로브 유형이라 누수가 없던 클립들이다.

## 5. 사전 분기 판별자 실패 (`probe_net_log.txt`)

"전면형이면 σ32, 아니면 base" 분기용 신호 두 개를 클립 단위로 측정:

- **net**(관문의 순방향성): cera 0.112 vs 누수 클립 CIHun 0.264 — 역전,
  분포 완전 겹침. 명멸 위상 때문에 쌍봉이라 클립 집계가 무의미.
- **a_hot**(10도 창 점유율): 거의 전 클립 1.0 포화 — 판별력 없음.

→ "국소 플래시라 샌다" 가설 기각. σ32 안전/누수를 가르는 인자는
플래시 영역 내부의 공간 주파수로 추정되나 싸게 재는 방법이 없다.
**사전 분기(방식 2)는 기각.**

## 6. 결론 및 제안

1. `detail_sigma=32` 기본값 승격 **불가** (플래시 미탐 2+1편).
2. `net_directional` 단독 승격은 유망 (플래시 미탐 0, 헤일로 이득 유지,
   화면전환 축 퇴보 3편) — 단독 설정으로 209 전수 재관문 필요.
3. 조건부는 **사후 폴백**으로: strong 1차 → 재검출 → strong 위반이
   base 위반의 부분집합이 아니면 base 채택. 판별자가 필요 없고 판정
   축에서 base 미만이 구성상 불가능. 근거용 strong 209 전수 판정 진행 중
   (`strong_209.csv`, 완료 시 추가 커밋).
4. 파이프라인에서 D(BlazeBVD) 슬롯은 제거하는 방향으로 합의.

## 7. 덤 — psegpu_full `-shortest` 크래시 버그

`_open_writer()` 의 `-map 1:a:0? -c:a copy -shortest` 조합은 **오디오가
영상보다 짧은 클립**에서 ffmpeg 가 오디오 종료 시점에 먼저 끝나 stdin
파이프를 닫고, `run()` 의 `writer.stdin.write()` 가 BrokenPipeError 로
죽는다. 실측: `_ig_safe/Db4MJViRU0P.mp4` (영상 64.07s, 오디오 62.34s) 에서
결정적 재현 — 209편 회귀가 158번째에서 중단된 원인. 우회는 `-shortest`
제거(판정은 오디오와 무관). 수정 시 `apad` 등으로 길이를 맞추는 편이 낫다.
